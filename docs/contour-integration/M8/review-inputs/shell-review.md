## 1. STRUCTURE

### How `app.ts` is organised

- **One closure.** `mountApp(root)` runs from `src/shell/app.ts:267` to `:3885`. Everything — state, DOM construction, render functions, gesture handlers, the pen, the drill, the codec glue, the figure export — is inside it. Roughly 45% of the file is commentary (design history), which inflates it but also means the *code* is closer to ~2,000 lines.
- **~60 module-level `let`s** hold the state: problem state at `:268–:293` (`view`, `poles`, `compiled`, `contour`, `resolved`, `integral`, `theorem`, `ledger`, `derivation`, `acc`, `scrub`, `contrast`, `highlight`), gesture state `:301–:396`, gallery state `:403–:445`, panel/drill state `:691–:692`, `:821–:839`, stage `:1257`, declaration `:1657–:1683`, hash `:1781`, `:1801`, a11y `:2392`, `:2401`, pointer `:3418–:3419`. Three separate "doors" write them: `applyState` (`:1936`), the gesture routes (`setMode` `:2125`, `loadRecord` `:2160`, `selectFixture` `:2169`, `applyExpression` `:2205`, `applyParam` `:2703`), and ~20 inline handlers that do `branch = …; recompute()` directly inside render functions (`:3000–:3140`, `:3193–:3300`) and in `pointermove` (`:3580–:3592`) / `moveGrab` (`:3676`).
- **DOM is built once, imperatively**, with a 10-line `el()` helper (`:192`). Layout skeleton `:453–:460`: `<main class="shell">` → `<header class="bar">`, `<div class="stage">` (two canvases + a DOM overlay), `<aside class="rail">`, `<footer class="strip">`. The rail's card order is fixed at `:1205–:1216`: `linkBox, errorBox, drillCard, recordCard, ledgerCard, derivationCard, resultCard, contourCard, branchCard, poleCard`. The bar is assembled at `:662–:673`. The contrast and drill panels are `position: fixed` overlays appended to `<main>` (`:799`, `:936`).
- **The recompute path** (`recompute`, `:2095–:2123`): `resolved = resolveAll(contour)` (sandbox) → `applyResolution(resolveState(currentState(), compiled, budgetNow()))` (`:2020`) → recompute handles → `rebuildDerivation()` → **eight render functions, each of which `replaceChildren`s its whole card** (`renderDrill :939`, `renderRecordCard :2274`, `renderLedger :2403`, `renderDerivation :2486`, `renderResult :2582`, `renderContourCard :2722`, `renderBranchCard :2964`, `renderPoles :3331`) → `drawAcc()` → `requestDraw()` → regenerate both canvas `aria-label`s → `syncHash()`.
- **Rebuilt vs kept.** Rebuilt on *every* recompute (which is every `pointermove` of a contour/handle/branch drag and every slider `input` tick): the entire rail below the error boxes, all `<details>` elements, all sliders, all `<select>`s, the pole `<div>` overlay (`drawPoleMarkers :1588` does `overlay.replaceChildren()` on every animation frame, including plain pans). Kept: the bar (built once), the contrast grid (built on first open, `:704`), the two canvases, the strip's controls. There is no keyed/diffed rendering anywhere and no teardown (`window.addEventListener("resize", …)` at `:3854` is never removed; `GLStage.dispose` exists but is never called).
- **Drawing** is coalesced through one rAF (`requestDraw :1285`): GL stage → `drawContour` (ink.ts) with `colours/highlight/marker/refused/cuts/handles` → branch handles → pen preview → pole DOM markers. `drawAcc` (`:1603`) is separate and not coalesced.
- **State projection** is clean: `currentState()` (`:1899`) and `applyState()` (`:1936`) map 17 fields to/from `ShellState`. `applyState` deliberately bypasses `setMode`/`loadRecord` and syncs the bar controls itself.

### Rewrite vs incremental refactor

**Rewrite the shell on the existing engine, keeping `state.ts`, `viewState.ts`, `drill.ts`, `contrastGrid.ts`, `figure.ts`, `templates.ts`, `ink.ts`, `accumulator.ts`, `glStage.ts` and the gesture machine.** Reasons:

1. Every owner decision that touches the rail (two rails, ledger collapsed, KaTeX, scrubbable numbers, hover readout, undo, textbook vocabulary) either relocates a card or requires the rail to *not* be thrown away on every recompute. The rebuild-everything model is the one architectural fact the current code depends on (§2 shows its user-visible costs), and changing it means rewriting all eight render functions anyway. KaTeX in particular cannot be re-rendered a dozen times per drag frame.
2. The engine contract is already the right shape: `ShellState → resolveState → StateResolution` (`state.ts:230–:396`). A new shell is `render(state, resolution)`; the closure's ~60 lets collapse into `ShellState` plus a small `Session` (gesture, pen, drill answers, undo stack, hover).
3. The history in the file itself (`:3145–:3153` shadowed-`branch`, `:2036–:2045` stage relink per frame, `:1490` stale card) shows the incremental path is where the bugs come from: parameter shadowing and cross-writes between renderers are what `no-shadow` was turned on for.
4. Incremental extraction would still have to invent a renderer boundary that doesn't exist, and most of the 3,886 lines are prose that would be moved, not code that would be kept.

Estimate: **L** for a two-rail shell with feature parity (mode switch, gallery, contour/branch editing, pen, drill, contrasts, permalinks, figure export, a11y); **XL** with all owner decisions folded in. The gesture code and pen logic are reusable and save perhaps a week of that.

## 2. INTERACTION GAPS AND DEFECTS

Ordered roughly by how amateurish they would look to a visitor.

1. **Every control in the rail loses focus, and every disclosure snaps shut, on any change.** `recompute` replaces all cards (`:2100–:2110`). Consequences: (a) the derivation `<details>` is recreated with `panel.open = !derivation.closes` (`:2498`) so opening it and then dragging the contour or nudging a slider closes it on the first frame; likewise the per-line `audit trail` details (`:2553`) and the record card's `how the golden value was verified` (`:2354`). (b) A parameter slider is destroyed on its own `input` event (`slider.addEventListener("input", …applyParam)` `:2811` → `recompute` → `renderContourCard`). Keyboard use: press an arrow, the slider vanishes, focus lands on `<body>`, the next arrow does nothing. Whether a *mouse* drag survives element replacement is browser-dependent — verify in Chromium/Safari before assuming the "drift" note at `:438–:444` was measured with a mouse. (c) The branch-order `<select>` (`:3106`), window `<select>` (`:3193`), sheet `<input type=number>` (`:3270`) and `log^m` input (`:3238`) are all destroyed after their `change`. **Difficulty: this is the reason for the rewrite (§1); with a keyed renderer it is free.** The pen test at `test/pen.test.ts:621–:644` already documents this class of defect for one card.

2. **No hover readout of z / f(z).** `pointermove` with no gesture only updates handle hover (`:3557–:3571`). The shell no longer even holds an evaluator (`:269–:273` says so); `applyResolution` receives `res.f` for plain/declared (`:2020`) and `run.f` for gallery but drops it. **S** (see §4l).

3. **No undo except the pen's Backspace** (`penBack :1516`). Dragging a contour across a pole, moving a cut, changing a determination, `undeclare`, picking a template — all irreversible. `currentState`/`applyState` are the snapshot mechanism. **S–M** (§4k).

4. **Slider drags run at full quadrature quality.** `budgetNow()` (`:1885`) drafts only when `gesture === "contour"`; a slider never sets `gesture`, so each `input` tick runs the full up-to-65,536-node quadrature (`DRAFT_EVALUATIONS` comment `:158–:165`). Near a pole this will visibly stutter. **S**.

5. **Parse failure leaves a stale phase portrait.** `applyExpression` on `!compiled.ok` (`:2207–:2214`) shows the error box and "No integrand." in the ledger, but the GL program of the *previous* expression stays on the stage (acknowledged at `:2218–:2222`). The picture and the box disagree. **S**.

6. **Pole markers are not in the exported figure.** Poles are DOM `div.pole` in the overlay (`:1588–:1600`); `figureBytes` composites only `[glCanvas, inkCanvas]` (`:1861`). Every exported PNG is missing its singularities. Real defect. **S** (draw poles on the ink canvas).

7. **Record picker shows slugs.** `opt.textContent = fam.id` (`:511`) — a mathematician sees `jordan-cosine-kernel`, `mellin-keyhole`, `log-cubed-keyhole`, grouped as `tier A … tier G`. `family.title` exists and is only shown after opening (`:2286`). **S**.

8. **The same poles are listed three times in three formats**: the Poles card (`:3331`), "Winding numbers (exact):" in the result card (`:2669–:2681`), and the derivation's per-pole table (`:2517–:2537`). **S** to unify in a new rail.

9. **Piece list is read-only** (`:2851–:2879`): a colour chip, name, role tag, value. Hovering a row highlights the piece on the stage (`pointerenter :2870`), but not the reverse; no click-to-select; no reorder/delete/reverse/add. List-level editing is entirely absent (§4e).

10. **Snap feedback appears in the wrong place.** The pen's `snapped to …` sentence is rendered in the rail card (`:2801`), while the reader is looking at the pointer on the stage. The preview colour `#7aa2f7` is hardcoded (`:1391`). Contour body/handle drags have no snapping at all; `radiusDragValue` returning `null` past the parameter's range (`:3588–:3591`) just makes the handle stop with no feedback.

11. **No "fit" / reset-view control.** `frameContour` (`:1631`) is called only when the contour is replaced; once panned or wheel-zoomed away (`:3825`, unclamped `Math.exp(-deltaY*0.0015)`, no `halfHeight` bounds) there is no way back except reopening the record. Double-click does nothing. **S**.

12. **Cursor inconsistency.** CSS sets `.stage { cursor: grab }` (`app.css:155`) but JS sets `default` whenever the pointer is not over a grabbable (`:3453`), so the cursor changes meaning after the first move, and "default" understates that the plane pans. **S**.

13. **Bar overflow at laptop widths.** `.bar` is `overflow: hidden` with `nowrap` pills (`app.css:57–:63`, `:107–:115`): brand + mode toggle + `f(z) =` input + 7 presets + Contrasts + Drill + Copy link + Save figure + Copy figure + status note. The narrow-layout test only measures ≤ 41rem; at 1280–1440 px the right-hand buttons are likely clipped. Verify in a browser. **S** in a redesign.

14. **URL sync is inconsistent for view-only fields.** `scrub` (`:3839`), `iso` (`:2904`), and `contrast` (`:1246`) are in the wire format (`viewState.ts` keys `s`, `i`, `k`) but their handlers never call `syncHash`, so the address bar only catches up on the next unrelated change. **S**.

15. **Overlay panels are not modal.** `.contrastPanel`/`.drillPanel` are `position: fixed; inset: 0; z-index: 10` (`app.css:613`) with Escape + focus return (`:775–:790`, `:907–:922`, good), but no `aria-modal`, no focus trap, and the app underneath is not `inert`: Tab walks out of the panel into the hidden bar. **S**.

16. **Keyboard grab cycling has no on-screen state.** `cycleGrab` (`:3652`) walks view → body → every radius handle → every branch handle (dogbone + two points + cut vertices is a long ring) with only a live-region announcement and a slightly thicker ring; no visible label of what is held.

17. **Contrast-mode buttons in the strip** (`:1244–:1254`) toggle a class but carry no `aria-pressed`, unlike the mode toggle (`:544`) and the modulus toggle (`:2903`).

18. **Minor**: `Alt suppresses snapping` (`:2790`) — on macOS the key is Option and `metaKey` also works but is undocumented (`:3497`). `endGesture` calls `releasePointerCapture` unconditionally on `pointercancel` (`:3602`); harmless in practice.
